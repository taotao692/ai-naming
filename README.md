# AI 起名台（三名一帖）

Vercel + 豆包（火山方舟）流式生成中文名字的网页应用：输入起名需求，AI 实时吐出 3 组名字与寓意，结果自动写入 Supabase。

支持 4 家模型切换：豆包（火山方舟）、DeepSeek、通义千问 DashScope、Kimi Moonshot。

---

```

├── api/
│   └── name.js         # 后端：Vercel Edge Function，流式代理 + 落库

├── dev-server.mjs      # 本地预览（不依赖 vercel login）

```

## 二、本地运行（三步）

```bash

cd ai-naming
npm install

# 2. 生成环境变量文件，然后填值（见第三节）
cp .env.example .env        # Windows PowerShell: copy .env.example .env

# 3. 启动
```

```bash

```

## 三、环境变量

写在 `.env` 里（本地），线上则配在 Vercel 项目 Environment Variables。**代码里没有任何硬编码密钥。**

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `SUPABASE_URL` | 是 | Project Settings → API → Project URL，只写到域名，**不要带 `/rest/v1`** |
| `SUPABASE_ANON_KEY` | 是 | API Keys → Publishable key（等价旧版 anon public） |
| `DOUBAO_API_KEY` | 用豆包时必填 | 火山方舟 API Key，`ark-` 开头 |
| `ARK_MODEL` | 用豆包时必填 | 接入点 ID（`ep-` 开头）或已开通的模型名 |
| `DOUBAO_THINKING` | 否 | 默认关闭深度思考；填 `on` 启用（首字会慢到 30s+） |
| `DEEPSEEK_API_KEY` | 可选 | `sk-` 开头 |
| `DEEPSEEK_MODEL` | 可选 | 默认 `deepseek-chat` |
| `DASHSCOPE_API_KEY` | 可选 | 通义千问，也可用 `QWEN_API_KEY` |
| `QWEN_MODEL` | 可选 | 默认 `qwen-plus` |
| `MOONSHOT_API_KEY` | 可选 | Kimi，也可用 `KIMI_API_KEY` |
| `KIMI_MODEL` | 可选 | 默认 `moonshot-v1-8k` |

没有配密钥的那一家，页面下拉框会**灰显「未配置密钥」并禁用**，不会影响其他模型使用。

示例 `.env`：

```env
SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxx
DOUBAO_API_KEY=ark-xxxxxxxxxxxxxxxx
ARK_MODEL=ep-xxxxxxxxxxxx-xxxxx
```

## 四、Supabase 建表

控制台 → **SQL Editor** → New query → 粘贴执行（表结构按老师给的参考 SQL）：

```sql
create table if not exists public.name_history (
  id               bigint generated by default as identity primary key,
  user_requirement text        not null,   -- 用户起名需求
  name_result      text        not null,   -- 三组名字与寓意
  model_name       text        not null,   -- 形如 doubao:ep-xxx
  created_at       timestamptz not null default now()
);

create index if not exists name_history_created_at_idx
  on public.name_history (created_at desc);

-- 调试阶段：直接关闭 RLS，最省事（详见 4.1）
alter table public.name_history disable row level security;
```

执行成功会显示 `Success. No rows returned`。

### 4.1 权限配置：调试 vs 正式

**调试阶段（关闭 RLS）**

```sql
alter table public.name_history disable row level security;
```

关掉 RLS 后，任何拿到 publishable key 的人都能读写这张表，调试期数据是测试数据，无所谓；但它等于「表对外全开」，**不能带到正式环境**。

**正式上线（开启 RLS，只写不读）**

```sql
alter table public.name_history enable row level security;

-- 新项目默认不会给 anon 表级 INSERT 权限，这一行必须加，否则报 42501
grant insert on public.name_history to anon;

drop policy if exists "name_history_insert_anon" on public.name_history;
create policy "name_history_insert_anon"
  on public.name_history
  for insert
  to anon
  with check (true);
```

这样配置后：前端用 publishable key 只能 INSERT，读不到任何历史记录；历史数据在 Supabase 控制台 Table Editor 里查看。**不建 SELECT 策略就是故意让读走不通。**

从调试切到上线，只需把上面两段分别执行一次（先 enable，再授权+建策略），不需要改代码。

> 如果哪天后端改用 `service_role`（Secret key）写库，可以删掉这条 anon 策略，只保留 service_role 写入——service_role 绕过 RLS，但仍不要放进前端。

## 五、使用

1. 左侧选模型（目前只有配了密钥的能选）
2. 选用途：人名 / 品牌 / 店铺 / 产品 / 角色 / 宠物
3. 填姓氏或关键信息，例如「姓江，女孩」
4. 填风格，例如「温润、书卷气，避开网红感」
5. 选字数，点「开始起名」

结果区会边生成边出现卡片：第一个名字通常 2–5 秒出现，整帖约 10 秒完成；右下状态显示「3 组 · 已存入 Supabase」。

生成完成后每张卡右上角可「复制」单个名字。

## 六、部署到 Vercel

**方式 A：从 GitHub 导入（推荐）**

1. 打开 https://vercel.com/new
2. 选择 `ai-naming` 仓库 → Import
3. Framework 选 **Other**，不用改 Build Command / Output Directory
4. 展开 Environment Variables，把 `.env` 里的四个变量逐个填上（SUPABASE_URL、SUPABASE_ANON_KEY、DOUBAO_API_KEY、ARK_MODEL）
5. 点 Deploy，等几十秒，拿到 `https://xxx.vercel.app`

**方式 B：命令行**

```bash
npx vercel link
npx vercel env add SUPABASE_URL            # 逐个粘贴，环境选 Production
npx vercel env add SUPABASE_ANON_KEY
npx vercel env add DOUBAO_API_KEY
npx vercel env add ARK_MODEL
npx vercel --prod
```

部署完成后访问 `https://xxx.vercel.app` 即可。`api/name.js` 使用 Edge Runtime，用来保证流式响应不被缓冲。

> `vercel env add` 需要给每个变量执行一次；改了变量要重新 `vercel --prod` 才生效。
> 环境变量没配全时，页面会直接报「未配置密钥」，这是预期行为。

## 七、技术说明

- **统一调用**：四家都使用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，`stream: true`；后端只维护一份 SSE 解析，把 `choices[0].delta.content` 拼成纯文本推给前端。
- **模型配置表**：`api/name.js` 里的 `modelConfigMap` 集中管理 baseUrl、密钥变量、模型名与额外参数；新增第五家只需加一条。
- **落库时机**：流读完时用累计的全文 insert 一次，成功后在流末尾追加 `<!--saved:1-->` 标记，前端据此显示「已存入 Supabase」。
- **首字延迟**：豆包默认带 `thinking: {type: "disabled"}`，首字从 36 秒降到 1.5 秒左右。
- **`model_name` 字段格式**：`doubao:ep-20261107141953-cx6pt`、`deepseek:deepseek-chat`，便于区分来源。

## 八、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 状态显示「未写入数据库」 | 表没建 / 缺授权 / 密钥错 | 重跑第四节的 SQL |
| 插入报 `42501 row level security` | RLS 开着但 anon 缺表级 INSERT 权限 | `grant insert on public.name_history to anon;` |
| 插入报 `PGRST205` | 表不存在 | 执行第四节 SQL（表名必须是 `name_history`） |
| 一直「正在起名 · 已等 20s」 | 模型在深度思考 | 确认 `DOUBAO_THINKING` 不是 `on` |
| `ModelNotOpen` | 账户没开通该模型 | 方舟控制台开通模型 |
| `InvalidEndpointOrModel.NotFound` | `ARK_MODEL` 写错 | 必须是 `ep-` 开头那串，或完整模型名 |
| `缺少 DOUBAO_API_KEY` | 线上没配环境变量 | Vercel 里补变量后重新部署 |
| 端口被占用 | 3000 已有服务 | `PORT=3001 node dev-server.mjs` |

## 九、安全注意

- `.env` 已在 `.gitignore` 里，**不要提交真实密钥**。
- `SUPABASE_ANON_KEY` 是公开级别的 key，配合「只写不读」的 RLS 使用是安全的；`service_role` / Secret key 绝不能放到前端。
- 若密钥曾外泄，去对应控制台吊销并重新生成。
